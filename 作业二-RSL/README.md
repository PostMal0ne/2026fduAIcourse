# 作业二 · RSL 系统：按题型自学习的模型路由

> 课程作业二（方案 b：自己做一个简单的 RSL 系统）的实现。
> 纯 Python 标准库 + 本地 Ollama，无第三方依赖、无 API 费用。

## 一句话

系统在本地两个模型（`qwen3:4b` 强、`qwen3:0.6b` 弱，后者快约 4 倍）之间做**路由**：
用「按题型分桶的 UCB1 + 收缩估计」从经验中学习"哪类题该交给谁"，
并在**模型没见过的题**上，用四类 baseline 与 95% 置信区间检验这种学习是否真的有效。

## 环境

| 项目 | 要求 |
|---|---|
| Python | 3.10+（只依赖标准库） |
| Ollama | 已启动（默认 `http://127.0.0.1:11434`） |
| 模型 | `qwen3:4b`（约 2.5 GB）、`qwen3:0.6b`（约 520 MB） |

```bash
ollama pull qwen3:4b
ollama pull qwen3:0.6b
```

## 运行

```bash
# 0) 不需要模型，先验证流程（10 秒）
python rsl.py --mock --outdir _mock

# 1) 数据集体检（检查训练/测试是否同分布、有无重复题）
python check_dataset.py --out tasks.json --out dataset_check.md

# 2) 正式实验：3 个 seed（任务集固定，只改变数据顺序）
python rsl.py --seeds 1 2 3 --rounds 4 --samples 8 \
              --per-kind-train 5 --per-kind-test 5 \
              --prior-weight 3 --lambda 0.2 --outdir .
```

产出：

| 文件 | 内容 |
|---|---|
| `report.md` | 实验报告（自动生成，含全部表格） |
| `curve.svg` | 在线累计准确率曲线 |

## 结果摘要

**实验规模**：3 个 seed ×（32 次在线调用 + 50 次测试矩阵调用）= 246 次模型调用，约 45 分钟，全部本机完成。

### 直接对比（测试集 25 题，95% Wilson 区间）

| 策略 | 准确率 | 平均延迟 |
|---|---|---|
| 随机选臂 | 82.0%（75.1%–87.3%） | 10.76 s |
| 全用弱模型 `qwen3:0.6b` | 64.0% | 2.48 s |
| **全用强模型 `qwen3:4b`** | **100.0%（95.1%–100.0%）** | 19.04 s |
| 在线 RSL（λ=0.2） | 74.7%（63.8%–83.1%） | 7.64 s |
| RSL（λ=0，只优化准确率） | 94.7% | 16.70 s |
| RSL（λ=0.1，延迟预算 12 s 内的最优取点） | **82.7%** | 11.60 s |

### 三条结论（完整分析见 [results/report.md](results/report.md)）

1. **强模型在本题库上封顶**：5 个题型全部 100%，所以准确率没有提升空间，任何交给弱模型的选择都只会掉分。这是本次实验最重要的方法论发现。
2. **路由的价值在延迟约束下**：当预算把强模型排除（12 s 预算）时，路由仍能拿到 **82.7%**，而"只能用弱模型"只有 **64.0%**（+18.7 个百分点）。成本—准确率前沿见 [results/frontier.md](results/frontier.md)。
3. **收缩估计是必需的**：不加收缩时，小样本噪声会让系统把简单题错配给弱模型（实测 75–85%，低于随机 82.0%）；加收缩后 λ=0 的策略退化回"全用强模型"，说明噪声已被抑制（详见 [docs/design.md](docs/design.md) 第 6 节）。

## 设计要点（详见 [docs/design.md](docs/design.md)）

1. **判分不依赖 LLM**：答案由程序生成、唯一正确，用正则抽取"答案："后比对 → 杜绝 reward hacking。
2. **训练/测试严格隔离**：测试答案只用于计分。
3. **按题型分桶**：不同题型难度差异大，全局单一策略会被某个题型主导。
4. **收缩估计**：题型内样本向该臂的全局均值收缩，抵抗小样本噪声（不加收缩时实测系统会比"一刀切"更差，详见设计说明第 6 节）。
5. **成本项进入训练**：`reward = 正确 − λ·(延迟/参考延迟)`，让"同样准但快 4 倍"真正有收益。
6. **可审计**：95% 置信区间、多种子重跑、策略切换率、错误类型分布、完整经验库。

## 复现说明

- 任务集由 `--task-seed 20261020` 固定生成，**三个 seed 共享同一套测试题**，因此三种子的结果可直接比较。
- `temperature=0` 但跨硬件/版本不保证完全一致；报告中的延迟是本机实测（RTX 3070 Laptop 8GB，Windows 11）。
- 重跑一次约需 30–35 分钟（3 seed × 82 次模型调用）。

## 已知局限

1. 题库限于可机器判定的数值/抽取题；开放式任务需要引入 LLM 裁判（如 Jev，$0.042/百万输入 token）。
2. 每个题型样本量有限，置信区间较宽。
3. 只有两个臂；更细的提示策略臂在开发中验证过，收益被成本抵消。
4. 延迟受桌面占用、电源模式影响，成本分析给的是相对量级。
